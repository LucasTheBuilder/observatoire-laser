## Environnement (pas un bug applicatif)

`pytest` échoue d'abord sur les 3 mêmes tests de `test_sitemap_pdf_ingestion.py`
(`pyo3_runtime.PanicException: Python API call failed`, `ModuleNotFoundError: No module named
'_cffi_backend'`), pour la même raison que le 19/10 : ce conteneur d'audit mélange un `pip`
système lié à Python 3.13 et l'interpréteur par défaut `python3`/`python` en 3.11, donc
`pip install -r requirements*.txt` via `/usr/bin/pip` installe dans le mauvais site-packages.
Correctif de contournement : `python3 -m pip install -r requirements.txt -r requirements-dev.txt`
(force le même interpréteur que celui qui lance les tests) puis `python3 -m pip install cffi`.
Après ça : 944 passed, 0 failed. La CI (`ci.yml`) installe sur Python 3.12 fraîchement dans un
runner propre et ne rencontre jamais ce conflit — rien à corriger côté dépôt. `ruff check .` :
« All checks passed ». `mypy .` : « Success: no issues found in 128 source files » (les notes
`annotation-unchecked` affichées sont informatives, pas des erreurs, et préexistantes).
